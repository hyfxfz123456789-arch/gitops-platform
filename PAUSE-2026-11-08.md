# CI/CD lab pause (2026-11-08)

The lab's Jenkins, Argo CD, and two `gitops-demo` workloads were scaled to zero. The `gitops-demo` and `gitops-demo-staging` Applications had automated sync disabled first, so Argo CD will not immediately recreate their Pods when restarted. Their previous replica counts were 1 and 2 respectively.

MySQL Operator had already been paused separately: its GitOps `manager-patch.yaml` sets controller replicas to 0, the four MySQL Pods are absent, and the backup CronJob is suspended. The MySQLCluster CR and five PVCs remain. The Jenkins PVC also remains. No namespaces, Helm releases, GitLab/Harbor data, CRs, or PVCs were deleted.

Ingress NGINX remains running because it also serves `kibana.lab`, `grafana.lab`, `prometheus.lab`, and `alertmanager.lab`. Metrics Server and unrelated monitoring/logging workloads were left running.

## Restore the CI/CD platform

```bash
kubectl -n argocd scale deployment/argocd-applicationset-controller deployment/argocd-dex-server deployment/argocd-notifications-controller deployment/argocd-redis deployment/argocd-repo-server deployment/argocd-server --replicas=1
kubectl -n argocd scale statefulset/argocd-application-controller --replicas=1
kubectl -n jenkins scale statefulset/jenkins --replicas=1
kubectl -n argocd get pods
kubectl -n jenkins get pods,pvc
```

To restore the demo applications as well:

```bash
kubectl -n gitops-demo scale deployment/gitops-demo --replicas=1
kubectl -n gitops-demo-staging scale deployment/gitops-demo --replicas=2
kubectl -n argocd patch application gitops-demo --type=merge -p '{"spec":{"syncPolicy":{"automated":{"selfHeal":true,"prune":false}}}}'
kubectl -n argocd patch application gitops-demo-staging --type=merge -p '{"spec":{"syncPolicy":{"automated":{"selfHeal":true,"prune":false}}}}'
```

To restore MySQL, create the saved `mysql-02` Pod from `/root/codex/project-study/mysql-operator-pause-20261031/mysql-02.json` and wait for it to become Ready. Then change `operator/mysql-operator/manager-patch.yaml` back to `replicas: 1` in the GitOps `develop` branch; Argo CD will start the Operator. Verify that the remaining MySQL Pods return and replication works before unsuspending the backup CronJob. The older pause guide contains a direct `kubectl scale` command; use the GitOps edit here instead because Argo CD now controls the Operator replica count. Do not delete the MySQLCluster CR or PVCs.
